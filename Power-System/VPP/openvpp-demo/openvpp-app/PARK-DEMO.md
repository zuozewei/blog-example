# 园区需求响应贯穿案例 · 手工核算底稿（教学假设）

> 全部数值为教学设定，不对应任何地区准入或结算规则。配套工程：`openvpp-demo/openvpp-app`。
> 关联标识：`responseId` 贯穿 任务 → 指令 → 基线 → 账单 四张表。

## 一、教学假设参数

| 项目 | 教学设定 | 说明 |
|---|---|---|
| 响应窗口 | 14:00—15:00 | 1 小时 |
| 核算粒度 | 15 分钟 | 共 4 个时段（point_index 0-3） |
| 各时段基线平均功率 | 1,000 kW | 相似日平均（教学样本 5 天均为 1000） |
| 各时段实测平均功率 | 400 kW | 模拟遥测 |
| 申报响应电量 | 600 kWh | declaredKwh=600 |
| 调度目标功率 | 900 kW | targetKw=900（下调） |
| 补偿单价 | 2 元/kWh | 教学假设 |
| 平台服务费率 | 10% | 分成部分计提 |
| 保底占比 | 50% | 保底总额按申报容量占比分 |

## 二、聚合可行性（第 14 篇口径）

| 资源 | 可调容量 | 置信度 | 可信容量 |
|---|---|---|---|
| 储能 ess-001 | 500 kW | 0.95 | 475 kW |
| 空调 ac-001 | 400 kW | 0.90 | 360 kW |
| 充电桩 ev-001 | 300 kW | 0.85 | 255 kW |
| **合计（折扣前）** | | | **1,090 kW** |

- 聚合可承诺容量 = 1,090 × 0.9（聚合折扣）= **981 kW**
- 任务 900 kW ≤ 981 kW → **可行**（降级路径剔除充电桩后见下文）
- 分配权重分母 = 有效能力之和 1,090 kW（**非**折扣后 981，两个口径不混用）
- 等比分配（3 位截断）+ 舍入残差补给有余量者：
  - ess-001 = 900 × 475/1090 ≈ 392.201 kW
  - ac-001 = 900 × 360/1090 ≈ 297.247 kW
  - ev-001 = 900 × 255/1090 ≈ 210.550 kW
  - 残差按剩余能力降序补齐，总和守恒 = 900 kW

## 三、响应量（第 17 篇口径）

- 各点正偏差 = 1,000 − 400 = 600 kW
- 响应电量 = 600 × 0.25 × 4 = **600 kWh**（缺失 0 点）
- 合格率 = 600 / 600 = **100%**（≥90% 不考核）
- 结算电量 = min(实际, 申报) = 600 kWh（超发按申报封顶）
- 偏差考核 = 0 元

## 四、结算与分摊（第 19/21 篇口径）

- 平台实收 = 600 × 2 = **1,200 元**
- 保底总额 = 1,200 × 50% = **600 元**
- 分成池 = (1,200 − 600) × (1 − 10%) = **540 元**
- 平台服务费 = 600 × 10% = **60 元**

| 用户 | 申报容量 | 保底（占比） | 实际贡献 | 分成（占比） | 应分合计 |
|---|---|---|---|---|---|
| user-storage | 500 | 600×500/1200=250.00 | 250 kWh | 540×250/600=225.00 | 475.00 |
| user-ac | 400 | 600×400/1200=200.00 | 200 kWh | 540×200/600=180.00 | 380.00 |
| user-ev | 300 | 600×300/1200=150.00 | 150 kWh | 540×150/600=135.00 | 285.00 |
| **合计** | 1,200 | 600.00 | 600 | 540.00 | **1,140.00** |

**资金守恒**：用户分摊 1,140 + 平台服务费 60 = **1,200 元** = 平台实收，分毫不差。

## 五、三条路径预期

| 路径 | 关键差异 | 预期 |
|---|---|---|
| NORMAL | 3 资源在线 | 可行，响应量 600 kWh，结算 1200 元 |
| DEGRADED | ev-001 掉线 | 可承诺 =(475+360)×0.9=751.5 kW < 900 → **不可行，返回缺口 148.5 kW**，不出账 |
| DISPUTED | 计量补到 | 同 NORMAL 完成结算，更正走冲正记录（保留旧版） |

## 六、验证方法

```bash
# 启动（零外部依赖，本地 H2 + 本地模拟设备回环）
mvn -s settings-openvpp.xml -pl openvpp-app -am -DskipTests package
java -jar openvpp-app/target/openvpp-app-1.0.0.jar

# 正常路径
curl -X POST "http://localhost:8080/api/v1/demo/run?responseId=run-001&path=NORMAL"
# 幂等重放（同一 responseId 再发，不重复执行/出账）
curl -X POST "http://localhost:8080/api/v1/demo/run?responseId=run-001&path=NORMAL"
# 降级路径
curl -X POST "http://localhost:8080/api/v1/demo/run?responseId=run-002&path=DEGRADED"
# 查询
curl "http://localhost:8080/api/v1/tasks"
curl "http://localhost:8080/api/v1/instructions?responseId=run-001"
curl "http://localhost:8080/api/v1/baselines?responseId=run-001"
curl "http://localhost:8080/api/v1/bills?responseId=run-001"
# 重置（清理后可再跑）
curl -X POST "http://localhost:8080/api/v1/demo/reset"
```
